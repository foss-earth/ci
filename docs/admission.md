# Trusted bootstrap and admission

Coordinator first reviews the initial common source, policy, fixtures and
complete selected-publication history locally. Only that reviewed ref is the
one-time bootstrap; it is not an ongoing exemption. Platform then installs that
exact archive in this repository, records its descriptor and pinned caller,
runs shared conformance, and supplies both source and self-adoption revisions.
Coordinator provisions and protects the remote, enables admission and proves
it before ordinary contributions. No source is pushed by these local tools.

In the hosted job the shared implementation comes from the reviewed SHA and
must match the byte hashes sealed into the immutable reusable workflow. The
subject is fetched as Git objects, never checked out or built. The trusted
release descriptor comes from the event's protected baseline. The PR's
replacement descriptor/validator cannot supply trusted policy. The exact Git
archive is recreated, verified against its baseline digest, installed with
scripts disabled into an ignored synthetic consumer, and shared conformance
checks the submitted caller/config and actual installed executable. Updating
the release descriptor or caller pin needs the separate trusted update path.
The workflow needs no application secrets and persists no checkout credentials.

A consumer can still replace/skip a PR workflow, so a reusable SHA caller alone
is insufficient prevention. GitHub required checks can accept skipped/neutral
conclusions. Coordinator must provide an external trusted required workflow or
controlled merge/admission service, protect policy/workflow changes separately,
restrict direct branch and tag writes and all bypass identities, and verify the
actual capabilities of each remote's plan. No post-push job is prevention.

PR-head metadata checks and merge-group candidates are evidence, not proof of
the final editable UI merge/squash message. The included candidate API constructs
and audits the exact final commit for controlled merge/squash. Coordinator's
service must validate its integration tree/tests and full publication ancestry,
bind proposed head and protected base, and atomically update only that candidate
using compare-and-swap. If either input moves, rebuild and re-audit. Never allow
an edit after validation. Disable UI merge/squash/rebase, direct pushes and
alternate admission methods unless the coordinator proves their exact final
metadata is checked before the protected ref moves. No privileged credential
may execute proposed application code. Rebase is not implemented here.

Required remote rehearsal, separately for every configured path: permitted
human contribution admitted; AI author, committer, coauthor each rejected;
edited final merge/squash attribution rejected; generated trailers checked;
same-PR validator/policy/caller replacement rejected; direct push/tag/bypass
attempts rejected; protected base drift rejected; merge queue covered when
enabled. Test in a designated isolated repository. Actual remote receipts and
per-repo configured check identity/application ID are required; representative
local regressions or one hosted example do not prove all remote adoption.

Primary references rechecked 2026-10-08:

Current tested platform is macOS arm64 with installed Node/Git; Ubuntu hosted
runner is specified but remains unqualified until the coordinator's rehearsal.
Private reusable workflow access and exact artifact distribution require
coordinator configuration. No hosted enforcement or other OS support is claimed.
